## §I — Interfaces (feminicides-specific)

```
file: data/raw/feminicidios_delegacion_{min_year}-{max_year}.json → feminicide reports 2003-2026, one Pydantic-validated report per year (regional/age/origin/relationship/cohabitation breakdowns; report-level source_page/confidence/verified, not per-category — V20); 2003-2005 legacy-format years now carry real regional/age/origin/relationship_type/cohabitation breakdowns (T63) — only prior_complaint/protective_measures/restraining_order_breach stay null (source is chart/graphic-rendered, not text, for those 3 fields only); real 2003-2005 headline totals also still live in `violence_spain.csv` via T1's manual entries (generated by T19/T20/T63)
file: data/processed/feminicide_rates_2006-2024.csv      → per-origin (Spanish/foreign) × per-role (victim/perpetrator) feminicide rate per 100k, 2006-2024 only, 4 rows/year (generated by T24,T60); T63's 2003-2005 age/origin backfill does NOT extend this file — population-adjusted rates for those years are out of scope here (would need pre-2006 population data, not pulled); CI columns removed (B35), denominators now use per-year Eurostat migr_pop1ctz stock_nationality per-nationality sex-specific rows (B34)
cmd:  `python src/parsers/feminicide_parser.py --pdf <pdf_path> | --pdf-dir <dir>` → parse one or all Delegación feminicide PDFs (2003-2026) → single `data/raw/feminicidios_delegacion_{min_year}-{max_year}.json` (T19,T20,T63)
cmd:  `uv run python src/feminicides/compute_feminicide_rates.py` → per-origin, per-role (victim uses female population, perpetrator uses male population) population-adjusted feminicide rates (T24,T60); reads Eurostat stock_nationality per-year per-nationality sex-specific rows for foreign-population denominators (B34)
file: `src/feminicides/build_dashboard_data.py`           → `build()` reads the feminicide JSON + rates CSV, emits `timeline` (2003-present, per-year age-band breakdown where available, hardcoded 2003-2005 fallback totals, provisional-year flag), merged `rates` (`years`/`latest_year`/`rows`, victim+perpetrator, full 2006-2024 series not just latest year), `relationship` (pareja vs. expareja + cohabitation, full 2003-2026 series, T97), and a static unsourced `milestones` array (`regional`/`age_origin`/`rates_2024` removed); consumed by `src/analysis/build_dashboard.py` → `docs/data/feminicides.json` (T23,T24,T60,T61,T97)
doc:  `data/sources/delegacion_gobierno_femicidio.md`    → manually curated feminicide figures, now sourced from the parsed JSON (see B22)
```

## §V — Invariants (feminicides-specific)

V8: Femicide rows ! distinguish registry: `Delegación_Gobierno` (partner/ex only) vs `INE_MNP` (all female homicide) vs `CGPJ` (judicial).

V40: `_extract_victim_perp_table()` (shared by the modern age-table and origin-table extraction in `_parse_modern_format()`) ! detect which of the two known layouts a block uses before slicing its Número/% token run: per-actor sub-blocks (`"Presuntos agresores"` appears AFTER the first `"Número"`, victim's own `Número`+`%` fully precede it — origin table, all years; age table, 2023+) vs flat single run (`"Presuntos agresores"` appears BEFORE the first `"Número"`, i.e. it's a column header not a section boundary — age table, 2006-2022 — real order is `[victim counts][perp counts][victim pcts][perp pcts]` across one `4n`-token window). ⊥ assume the per-actor layout unconditionally; a block whose real layout is flat and gets sliced as per-actor finds zero `Número` tokens before the (mis-identified) split point and silently returns `[]` (B33).

V42: Feminicide-rate population denominators (Spanish-resident vs foreign-resident split) ! derive from the real per-year per-nationality sex-specific stock in `migration_spain.csv`'s `stock_nationality` series (Eurostat `migr_pop1ctz`), not from a constant share ratio applied to a single year's sex split. `stock_nationality` carries the joint age(5yr)×sex×citizenship cross for ~49 nationalities covering ~86% of INE ECP foreign stock; the residual ~14% (small nationalities not in the top-50 list) is a known coverage gap documented in the source notes. ! apply a frozen ratio across years as a population estimate (B34).

V43: Wald 95% CIs on raw counts (count ± 1.96·√count) ! be presented as a useful uncertainty measure for feminicide rates — the CI captures only Poisson count variance (trivially narrow for N=24-50), not population-denominator uncertainty, and adds visual noise without analytical value. CI computation, CSV columns (`ci_lower`/`ci_upper`), dashboard tooltip fields, and HTML caveat text are all removed (B35).

V39: 2003-2005 legacy "ficha resumen" PDFs ! be checked against the T19 validation gate the same as modern years — sum(nationality) = sum(age) = sum(regional) = total_victims/total_agresores exactly — before a block is trusted; a block whose extracted number-count doesn't match its expected vocab length, or whose count sub-total doesn't reconcile, ! be left null rather than mis-zipped or trusted. Gated **per-block, not per-report** (B32): each of victim-nationality / perp-nationality / victim-age / perp-age / regional is validated independently, so one source-data inconsistency (real PDFs have isolated single-row rounding errors, e.g. 2004/2005) only nulls that specific block/side rather than discarding an otherwise-clean year; `confidence` is `"medium"` only if every block for that year passes, `"low"` if any block fails (with `notes` naming which). Legacy age brackets (8 coarse bands, e.g. `<16 años`/`16-17 años`/`51-64 años`/`>64 años`) are a structurally different, coarser resolution than the 10 modern bands (2006+) for the same `age` field — consumers ! treat the per-year age-band label set as year-varying, not a fixed global vocabulary (already true of `docs/app.js`'s `bandLabels` union + `ageMidpoint()`, which derives the color/sort key generically from each label's own digits rather than assuming a shared bracket scheme).

V41: `build_dashboard_data.py`'s `timeline.age_breakdown` ! use one canonical age-band vocabulary (`CANON_AGE_BANDS`, 8 bands) across every year, not the raw per-year label set (which V39 already flags as legitimately year-varying at the parser/raw-JSON level). `AGE_BAND_REBIN` maps both the legacy 8-band and modern 10-band raw vocabularies down to the canonical set: under-18 bands collapse to a single `<18 años` bucket on both sides (legacy `<16 años`+`16-17 años`; modern `13 a 14 años`+`15 a 17 años`); modern's three oldest bands (`61 a 70`/`71 a 84`/`85 años o más`) collapse into legacy's single `>64 años` (not `51-64 años`) since legacy has no finer resolution to split into and most of the `61 a 70` span (65-70) falls past 64 — this is an approximation, not an exact re-derivation, and is stated here so a future contributor doesn't "fix" the apparent boundary mismatch without knowing it's deliberate. `docs/app.js`'s `ageMidpoint()` handles the resulting `<18 años` label the same way it already handles `>64 años`/`o más`/`+` (open-ended-high, `+7.5y` past floor) but for the open-ended-*low* end instead (`N/2`, not `N+7.5`) — the pre-existing `<16 años` handling (added by T63) had this backwards (computed 23.5y for a *below-16* band) but was never visibly wrong until this rebin made `<18 años` a real, populated band for 2006-2022 too.
